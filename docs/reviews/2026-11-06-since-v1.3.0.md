# Figlets since 1.3.0

**Historical review.** Its findings describe the November 6 checkpoint, not the current candidate. The approved follow-up fixes and current limitations are recorded in the [1.4.0 release summary](../releases/1.4.0.md) and [current task list](../figlets-improvement-task-list.md). Do not treat the older action items below as still-unimplemented work without checking those records.

**Review date:** November 6, 2026  
**Comparison:** release `v1.3.0` (`35c2ebf`) to current checkout (`ceacca0`), 14 commits.

## Verdict

**The capabilities improved, but the designer experience is not consistently stable yet.** This is not explained by a model change alone. The review reproduced a stale running server, two logic gaps, and contradictory instructions. Keep the changes, resolve these issues, then verify the designer flows before publishing.

## Human changelog

| Area | What changed after 1.3.0 |
| --- | --- |
| DESIGN.md | Updated to Google's 0.4.0 format. Responsive values and useful color/elevation details are retained. Exact Figlets data moves into an optional companion JSON file instead of an inline extension. |
| Motion and opacity | Added native timing/easing values, optional motion foundations, shared opacity primitives, and composed colors. Existing scrims can migrate without changing their IDs. |
| Safer updates | Variable-value batches validate first, restore attempted changes after failure, and distinguish successful, unchanged, blocked, and uncertain results. Structural edits have a separate, weaker guarantee. |
| CSS and Make | Export milliseconds, percentages, resolved colors, and portable easings. Springs retain their exact data with portability warnings rather than invented CSS. |
| Component handoffs | Resolve transitive library aliases and retain more binding details. Motion timelines are still outside the documentation generator's inspection scope. |
| Designer flow | Names come from configuration or designer confirmation. The 44px AAA target-size advice no longer blocks export. Raw primitives are valid inventory, and missing internal configuration is prepared automatically. |

The six main designer workflows and approval-before-Figma-write boundary remain in place.

## Findings to address

### 1. High priority: the running server is behind the checkout

On the exact same snapshot, the connected `audit_tokens` tool reports **7 opacity defects / 0 opacity inventory entries**. Current-source execution reports **0 defects / 7 inventory entries**. This directly explains the earlier raw-opacity message. Both implementations identify as **1.3.0**; plugin manifests still point to the published 1.3.0 tarball.

**Action:** reconnect the development runtime, verify its build identity, and publish the next release with a distinct version. Passing a freshly built package check does not update an already-running server or the published release.

### 2. Confirmed logic gap: name confirmation does not survive refresh

Reproduction: create an imported-system configuration with a confirmed name, run `ensureActiveDsConfig` with generated refresh enabled, then preview DESIGN.md. The name text survives, but `projectNameSource` changes from `designer-confirmed` to `file-name-suggestion`. Export asks for confirmation again.

**Action:** preserve confirmed-name provenance during refresh and test the full confirm → refresh → export sequence.

Evidence: `packages/figlets-mcp-server/src/utils/ensure-ds-config.js:72-95`.

### 3. Confirmed logic gap: imported systems inherit unchosen expectations

Reproduction: inspect typography/shadow primitives in a color-only imported system with no existing internal model. Figlets automatically creates the model, then proposes **44 missing variables**, including standard type weights, sizes, and shadow values. Those expectations come from Figlets' generated defaults, not designer-approved requirements for that imported system. It does not write them automatically, but the “missing” framing is misleading.

**Action:** distinguish observed foundations, explicit design decisions, and optional additions. Offer unchosen defaults as optional setup, not defects.

Evidence: `packages/figlets-mcp-server/src/tools/inspect-ds-token-gaps.js:753-770` and the fixed foundation tables in `packages/figlets-core/src/ds-config/generate-primitives-data.js`.

### 4. Instructions are not fully aligned

The older setup-repair prompt says Figlets cannot rename/delete variables or edit primitive colors, although current tools support those approved operations. It calls near-miss contrast “usually fine,” builds payloads from older finding fields, and makes rechecking optional. The export prompt still exposes configuration work, treats all follow-up questions as optional, and does not explain the new nonblocking AAA advice. Adapter recovery copy still tells designers to add colors to a config file.

**Action:** synchronize prompts, adapters, and workflow guidance. Use one designer-facing contract and test representative answers, not only individual phrases. Treat these as older guidance that remains in use, not entirely new regressions.

Evidence: `docs/prompts/setup-gap-repair.md`, `docs/prompts/export-design-md.md`, and `packages/figlets-adapter/AGENTS.md:226` / `CLAUDE.md:226`.

## Model versus product

The model chooses wording, explanations, routing, and component usage guidance. Figlets code controls token analysis, contrast calculations, planned operations, generated files, and most Figma rendering. A different model can change the conversation, especially when instructions conflict. It cannot explain the measured seven-versus-zero audit discrepancy on its own. No controlled same-build, same-file comparison across models was performed.

## Verification and limits

- **133/133 test files pass**, compared with 122 test files in release 1.3.0.
- Release-package verification and packed plugin smoke checks pass.
- Two additional isolated scenarios reproduced the name-refresh and imported-default issues despite that passing suite.
- Compared source, prompts, adapters, project memory, decisions, feature execution records, gap register, historical smoke evidence, and existing generated component output. Historical notes were checked against current code and the release diff rather than treated as current truth.
- No Figma mutations, production-code fixes, model changes, publishing, or connection restarts were performed during this review. Existing visual confirmations are historical evidence; this was not a fresh visual regression pass across all six workflows.

**Recommended order:** align the running build → fix the two logic gaps → synchronize all prompts → replay the six designer workflows → version and release.
